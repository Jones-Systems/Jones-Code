# Workstreams T3 provider 1.0.0

Authority effect: none. This separate family leaves Workstreams v1 and placement contracts unchanged. Both consumers pin identical schema and synthetic fixture bytes through this manifest. Manifest paths resolve relative to this family directory.

Four authenticated operations live under `/api/workstreams/native/v1`: GET `context`, POST `attestations`, POST `settlements`, and POST `settlements/lookup`. The operation envelopes in the schema are internal discriminated unions; each HTTP body uses its operation-specific request definition. Context has an empty request. The protocol literal fences response versions. Transport owns 32,768-byte request and response caps, JSON depth 10, no redirects, metadata timeout 5,000 ms and settlement timeout 15,000 ms. An attestation is valid for 300,000 ms. Dedicated enrolled scopes do not grant thread content or general command access.

Context reports the enrolled owner, principal, source, authority namespace, store generation, enrollment and actual package build repository/sha/tree. An attestation observation must fence the targeted thread shell with before/after authority readbacks. The digest binds that closed observation and does not confer authority.

Schemas prove shape, fixed T3 identity kinds, bounds, calendar timestamps and closed records. The enrolled transport evaluator additionally compares every caller/source/build/authority field, echoes the exact request, verifies the attestation time window, and verifies result association/digest. The two successful mismatch fixtures explicitly require evaluator rejection; they are structurally valid and confer no authority. `native_evidence` mirrors the registry's immutable owner/principal/command/reference/action/request/reservation association plus result digest. Result SHA-256 covers canonical JSON of that association plus `native_outcome`, using the registry canonicalization.

A committed terminal requires an accepted durable native receipt and attributed settlement event. The evaluator matches native command ID, thread aggregate, result sequence and event type against the requested action. Receipt/event records are metadata projections: no error text, thread detail, payload or messages. Denied/unsupported/failed terminals require trusted attempt evidence and preserve native policy. A null receipt is valid for a trusted pre-dispatch rejection.

Persist the immutable full request and server-derived native command ID before invocation, and dispatch-start before calling the engine. Same ID with different request bytes conflicts. A started attempt is observed and never dispatched again. Missing or contradictory receipt/event evidence is unknown. After timeout or lost response, use lookup exclusively; unknown and rejected responses do not authorize another invocation.
