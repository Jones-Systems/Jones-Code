# Workstreams registration context 2.0.0

Authority effect: none. This additive family preserves the frozen registration-context v1, Workstreams v1, placement, and native-provider contracts. Manifest paths are relative to this directory; each file digest covers its exact bytes. The manifest digest hashes sorted `<file-sha256>  <relative-path>\n` records, excluding manifest.json itself.

Use signed empty GET `/workstreams/v1/t3/registration-context` with the exact version `workstreams-registration-context/2.0.0` and this family's manifest digest. Both authentication and the route require the version/manifest pair; responses echo it. HMAC signing binds the contract version, identity, method, target, and body digest; the existing signing format does not include the manifest header. The fixed version-to-manifest mapping is therefore checked separately. Neither the request nor route accepts a body, query, caller-selected identity/source, or browser identity headers. Responses are limited to 8,192 bytes and JSON depth 10, with `Cache-Control: no-store`.

The closed ready response binds the current durable owner/principal/read grant, grant revision, server generation, and registry version. Its sources are the intersection of exact configured descriptors and current active registry source bindings. It permits zero through four T3 thread sources and at most one GitHub pull-request source. Native-provider protocol remains `workstreams-t3-provider/1.0.0`; provider kinds, authority semantics, and per-source enrollment remain unchanged. Metadata is not a native health or credential-readback receipt.

Stable source identity is the pair `(provider, source_instance_id)`. Every pair must be unique, regardless of generation, namespace, or build. Schema validation enforces structure and cardinality; consumers must additionally reject semantic duplicate identities. `fixtures/semantic-cases.json` contains structurally valid responses that this semantic validation must reject. A consumer must match its own exact trusted source and authority context without choosing by order, hostname, or native thread ID. Unknown or ambiguous sources fail closed.

T3 descriptors expose the native protocol and Jones repository/sha/tree build; GitHub descriptors omit those fields. Sources expose no origins, credential locators, credentials, headers, session IDs, native IDs, thread content, or private fields. Account provenance remains not account scoped. Current authorization, active binding/configuration equality, and locally trusted native authority are independent of structural validation.

V1 requests retain their exact v1 response and limits. If the active configured intersection contains more than one T3 source, v1 fails closed; it never truncates the set, silently upgrades the response, or falls back to a different source. V2 consumers explicitly pin this family and producer revision.
